# 第 18 章：综合练习、验收标准与进阶路线

本章不是新的知识堆叠，而是把整本教材变成可执行路线。每一阶段都以当前多传感器项目为实验平台，要求“能解释、能修改、能测量、能恢复”。

## 18.1 总原则：先稳定基线，再做实验

每个实验前：

1. 确认裸机/FreeRTOS 原版至少一个可正常 Build、Download、Run；
2. 记录 Keil target、优化等级、硬件接线和 UI 主题；
3. 复制实验 target 或使用版本控制分支；
4. 一次只验证一个概念；
5. 保留串口/LED/Map 等证据；
6. 实验失败能在 5 分钟内恢复稳定版本。

不要把“教材练习代码”直接连续堆到唯一可烧录 target 中。

## 18.2 阶段 0：工程和硬件基线

### 学习内容

- 根目录接线、Keil 编译下载、UI 操作和 ST-Link 排障文档；
- 两个工程目录结构；
- I2C 地址和 SPI 引脚；
- Classic/Nokia 主题切换；
- EC11 旋转 + PB15 短按/长按。

### 实验

1. 裸机版 Build，记录 Code/RO/RW/ZI；
2. 下载后确认 OLED、四类传感器、时间、Flash JEDEC；
3. 切换主题并断电重启，验证设置持久化；
4. FreeRTOS 版重复；
5. 拔掉一个 I2C 模块，记录启动日志与降级行为。

### 验收

- 能明确区分 Build、Download、Debug、Run；
- 能根据 Keil 输出判断下载是否已经成功；
- 能画出全部当前接线；
- 能在源码中找到一个功能的 header、implementation、调用者、配置。

## 18.3 阶段 1：C 基础与位运算

### 学习内容

- 固定宽度整数、浮点、表达式、控制流；
- 十六进制、二进制、位掩码；
- 有符号/无符号、整型提升、回绕。

### 项目练习

1. 给快照增加一个仅 RAM 使用的 `APP_VALID_*` 位；
2. 写函数统计 valid mask 中置位数量；
3. 写定点格式化：把 `2534` 输出为 `25.34`；
4. 写回绕安全的 `time_reached()` 并在 PC 测 `UINT32_MAX` 附近。

### 验收题

- `0x44 << 1` 为什么是某些 HAL I2C API 所需地址？
- `1 << 31` 与 `1UL << 31` 有什么潜在差别？
- 为什么毫秒 tick 应使用无符号数保存，却可用有符号差值判断？

## 18.4 阶段 2：函数、模块与接口

### 学习内容

- 声明/定义、头文件、链接；
- `static`、`extern`、作用域和生命周期；
- 输入/输出参数、返回码、前置/后置条件。

### 项目练习

1. 新建一个纯 C `system_metrics` 模块；
2. header 只公开查询/更新 API；
3. `.c` 内 `static` 保存事件丢失、I2C 错误、最大任务耗时；
4. UI 诊断页读取快照，不直接修改内部状态。

### 验收

- 任何全局状态都有唯一所有模块；
- header 可单独包含且有 include guard；
- 不通过 `extern` 暴露所有内部变量；
- 错误码含义和输出参数失败行为写清楚。

## 18.5 阶段 3：指针、数组与内存

### 学习内容

- 地址、解引用、pointer arithmetic；
- array-to-pointer decay；
- const 三种位置；
- 字符串终止、缓冲区边界、对象生命周期。

### 项目练习

1. 手工计算 OLED 任意像素 index/mask；
2. 写 `buffer_set_pixel(uint8_t *data, size_t length, x, y)`，先验证边界；
3. 给 I2C 扫描函数增加输出容量参数，确保不越界；
4. 用 PC AddressSanitizer（若可用）故意测试越界版本和修复版本。

### 验收

- 能解释 `sizeof(array)` 与函数内 `sizeof(pointer)`；
- 能指出返回局部数组指针为何错误；
- 能读懂 `const uint8_t *`、`uint8_t * const`、`const uint8_t * const`。

## 18.6 阶段 4：结构体、协议与数据结构

### 学习内容

- 结构体对齐/packing；
- enum/union；
- ring queue、复杂度、状态机；
- 序列化、CRC、版本。

### 项目练习

1. 在 PC 解析当前 32 B 日志记录；
2. 实现固定 16 项 ring queue 并测试回绕；
3. 设计 V2 日志格式但不破坏 V1 读取；
4. 手工 little-endian 序列化，比较 `packed struct` 写法；
5. 给设置记录增加 generation 并设计回绕比较。

### 验收

- 队列空/满/回绕测试全部通过；
- 能算出 64 KiB 区域 2048 条和保存时长；
- 断电留下半条记录时可由 magic/CRC/commit 规则拒绝。

## 18.7 阶段 5：STM32 内核和外设

### 学习内容

- Cortex-M3、存储映射、时钟；
- GPIO 输入/推挽/开漏；
- EXTI/NVIC/SysTick；
- I2C/SPI 时序。

### 项目练习

1. 从 `board_init` 追踪 PB15 到寄存器配置；
2. 逻辑分析仪抓 OLED 地址和一条数据；
3. 抓 W25Q64 `0x9F` JEDEC 命令；
4. 在 EC11 EXTI 入口翻转测试引脚测中断频率；
5. 用 DWT 或 GPIO 测一次传感器服务调用。

### 验收

- 能从故障波形判断 NACK 在地址还是数据阶段；
- 能解释为什么 I2C 高电平由上拉形成；
- 能解释 ISR 自动压栈和为何 ISR 要短。

## 18.8 阶段 6：裸机微型系统

### 学习内容

- 周期任务、deadline、漂移；
- 函数指针和 context；
- 事件总线；
- 非阻塞状态机；
- WFI。

### 项目 A：运行统计器

为每个任务记录：

```c
typedef struct {
    uint32_t calls;
    uint32_t max_cycles;
    uint32_t max_lateness_ms;
    uint32_t missed_periods;
} task_metrics_t;
```

低频打印，不在每次调用打印。

### 项目 B：全非阻塞蜂鸣器

- 请求 `beep(duration)` 只设置状态；
- 周期 service 自动关闭；
- 新请求的合并/覆盖策略明确；
- 有最大持续时间硬限制；
- Error_Handler 仍立即关闭。

### 项目 C：传感器分阶段

把一秒一次的批量读取分成 4–6 个阶段，在完整周期结束后一次提交 snapshot。

### 验收

- 任一普通任务最坏调用时间有测量；
- Flash 擦除期间编码器仍响应；
- 队列 dropped 与 high-water 可观察；
- 任务没有无超时等待。

## 18.9 阶段 7：FreeRTOS 并发

### 学习内容

- task state、priority、preemption；
- queue/overwrite、mutex、notification；
- task stack、高水位；
- ISR priority 与 FromISR。

### 项目 A：诊断 health task

每 10 秒输出：

- 五任务 stack high-water；
- 四队列发送失败/峰值；
- I2C mutex 最大等待与持有时间；
- Flash 写错误；
- uptime 与 reset cause。

### 项目 B：编码器 EXTI + task notification

ISR 只累计状态并通知 encoder task，任务解码/消抖/发 UI 队列。验证中断优先级允许 FromISR API。

### 项目 C：FreeRTOS 异步 Flash

把裸机 storage state machine 移植到 storage task：忙时 `vTaskDelayUntil` 或通知唤醒，不持续轮询 CPU。

### 验收

- 无忽略的关键 queue send 失败；
- 每把 mutex 的所有访问者和锁顺序文档化；
- 最重路径下各任务栈保有合理余量；
- 同步 Flash 写期间 health/encoder 不饿死。

## 18.11 阶段 9：继承、模板与架构选择

### 项目 A：两种传感器抽象

分别实现：

- C ops table；
- C++ virtual Sensor。

对比对象大小、调用方式、扩展一个 fake sensor 的改动。

### 项目 B：固定模板队列

实现 `FixedRingBuffer<T,N>`，测试不可复制/大对象或移动语义选择。

### 项目 C：主题策略

分别用 `switch`、virtual interface、variant（现代 PC 编译器）表达 Classic/Nokia；比较复杂度和二进制。

### 验收

- 能说明为什么组合通常优先于继承；
- 知道虚表典型成本但不把实现细节当标准保证；
- 能用 map/反汇编验证模板和虚调用，而非口头判断。

## 18.12 阶段 10：嵌入式 C++ 实验目标

### 验收

## 18.13 阶段 11：可靠性版本

### 功能

- reset cause；
- fault record；
- IWDG 健康喂狗；
- I2C bus recovery + error backoff；
- Flash commit marker/A-B 设置；
- 数据 stale age；
- 诊断页面；
- 24/72 小时测试。

### 验收

- 人为让一个关键任务停止，IWDG 按预期复位并记录原因；
- 人为产生可控 fault 后能得到 stacked PC；
- Flash 写一半断电后旧/新设置至少有一个有效；
- 单传感器掉线不会拖死总线和 UI；
- 72 小时 dropped/error/reboot 结果可汇总。

## 18.14 阶段 12：性能对照报告

裸机与 FreeRTOS 使用相同驱动功能后，测量：

| 指标 | 裸机 | FreeRTOS | 解释 |
|---|---:|---:|---|
| Flash Code/RO | | | 内核/库/驱动差异 |
| SRAM RW/ZI | | | 任务栈/队列/双缓冲 |
| 输入到显示 P50/P99 | | | 抢占/最长阻塞 |
| OLED 小改 I2C 字节 | | | 驱动需一致 |
| Flash 擦除时输入延迟 | | | 状态机/任务阻塞 |
| 空闲 CPU/功耗 | | | WFI/idle/tick |
| 24h I2C errors | | | 恢复和锁 |
| 丢输入/日志 | | | 队列策略 |

不要只给“FreeRTOS 更流畅”或“裸机更快”的结论。报告必须说明测试版本、业务行为和驱动是否一致。

## 18.15 综合毕业项目：可维护的环境终端

### 必选功能

- 四类传感器 + RTC；
- Nokia 四宫格与 Classic 主题；
- EC11 + PB15；
- 设置持久化；
- 日志环形记录；
- 诊断页面；
- 错误降级；
- 全非阻塞蜂鸣器；
- 看门狗健康策略；
- Map/性能/长测报告。

### 可选功能

- UART 命令导出 CSV；
- 串口设置时间；
- 日志浏览折线图；
- WS2812 低亮状态指示（需要独立 5 V、电平转换、限流/去耦）；
- USB CDC；
- Bootloader；
- SHT30/BMP280 校准偏移；
- PC 配套日志解析器。

### 架构验收

- 驱动、服务、UI、系统层依赖方向明确；
- 无 UI 直接访问寄存器；
- 无 ISR 做 OLED/Flash 长操作；
- 无无界等待；
- 持久化格式有版本和 CRC；
- 所有共享资源有所有者/同步合同；
- 资源预算和最坏时间有数据。

## 18.18 最终自测题

如果下面问题大部分能独立回答，你已经从“会照着写”进入“能设计和解释”：

1. STM32 为什么从 `Reset_Handler` 开始？
2. `.data`、`.bss`、stack、Flash 各是什么？
3. `volatile` 能做什么、不能做什么？
4. I2C 为什么要上拉，五块板并联有什么问题？
5. OLED 像素怎样映射到 1024 字节？
6. 双缓冲为什么可能提升性能却增加 SRAM？
7. W25Q64 为什么不能像 RAM 覆盖写？
8. 裸机任务为什么必须短返回？
9. 事件与状态为什么不总用同一种队列？
10. FreeRTOS mutex 为什么有优先级继承？
11. 每任务栈为什么是 RTOS 主要 SRAM 成本？
12. C 函数表与 C++ vtable 有何联系？
13. RAII 为什么适合 SPI CS 和 mutex？
14. 模板为什么可能零开销，也可能代码膨胀？
15. C/C++ ABI 边界为什么需要 `extern "C"`？
16. O2 锁死为什么可能是 UB？
17. 看门狗正确喂法为什么需要健康汇总？
18. 下载成功后 Debug 失败为什么是另一阶段？
19. 如何用数据证明一次优化有效？
20. 如果新加一个传感器，你会改哪些层，如何保证其他设备不受影响？

教材正文到此形成闭环。附录提供术语与常用速查，`Examples` 提供可在 PC 独立编译的练习代码。
