# 附录 B：检查点提示与参考答案

请先独立回答，再阅读本附录。参考答案强调判断依据，不是要求逐字背诵。开放设计题通常没有唯一实现，关键是说明合同、成本、失败路径和验证方法。

## B.1 第 1 章：项目与程序运行

### 为什么 Keil Build 成功不代表能运行

Build 只验证源文件能经过编译和链接形成映像。后面还有：

- ST-Link 与目标供电/连线；
- Flash 下载和校验；
- 启动文件/时钟/中断；
- 外设接线、地址和电平；
- 业务运行路径。

错误必须按阶段定位。`Verify OK` 后的 Debug 连接失败，不应回头乱改 C 代码。

### `.h` 和 `.c` 的基本分工

`.h` 声明外部可依赖的类型和 API；`.c` 定义实现并用文件内 `static` 隐藏细节。头文件被多个翻译单元包含，通常不能定义可写全局对象。

## B.2 第 2 章：C 类型与二进制

### 为什么使用 `uint32_t`

它明确表示恰好 32 位无符号整数，适合寄存器、tick、协议字段。`unsigned long` 在不同平台可能不是同样宽度。

### `valid_mask & APP_VALID_SHT30` 与 `&&` 的区别

`&` 是逐位与，用于提取某一 bit；`&&` 是逻辑与，把操作数按真假处理并短路。检查位应写：

```c
if ((valid_mask & APP_VALID_SHT30) != 0U) { }
```

### `1 << 31` 为什么有风险

字面量 `1` 类型为 `int`，移入符号位可能产生未定义行为或不可移植结果。写 `1UL << 31` 或与目标类型匹配的 `UINT32_C(1) << 31`。

### tick 为什么会回绕

32 位无符号计数每 2³² ms 回到 0，约 49.7 天。无符号减法按模 2³² 定义，因此在跨度小于半范围时可用差值判断相对先后。

## B.3 第 3 章：函数与多文件

### declaration 与 definition

声明告诉编译器名字和类型；定义提供函数体或对象存储。一个函数可在多个翻译单元通过头文件重复声明，但程序应只有一个外部强定义。

### 输出参数失败时怎么办

必须写进接口合同。稳妥选项：

- 失败时完全不修改输出：先构造局部结果，成功后提交；
- 失败时清零并返回详细错误；
- 返回结构化结果对象。

最差的是留下半更新数据却没有标志。

### 为什么模块内部变量用 `static`

内部链接防止其他文件直接依赖或改写它，避免符号冲突，让模块不变量有唯一维护位置，并利于优化。

## B.4 第 4 章：指针、数组与内存

### 数组和指针是否相同

不同。数组对象包含 N 个连续元素；指针对象只保存地址。数组表达式在多数场景转换为首元素指针，但 `sizeof array`、`&array`、字符串初始化等场景保留数组性质。

### 为什么函数参数 `uint8_t data[128]` 不能得知 128

函数参数中的数组写法会调整为指针参数。函数内 `sizeof(data)` 得到指针大小，而不是调用者数组大小。必须另传 length，或在 C++ 用数组引用/`std::array`/span。

### 为什么不能返回局部数组地址

自动对象在函数返回时生命周期结束。返回地址成为悬空指针，随后访问是未定义行为。

### OLED `(x,y)` 映射

```text
index = (y / 8) × 128 + x
mask  = 1 << (y % 8)
```

同一字节表示同一 x 列上的 8 个垂直像素。

## B.5 第 5 章：结构体与数据模型

### 为什么结构体可能大于成员大小之和

编译器为满足成员和结构体对齐插入 padding。成员顺序会影响 padding。

### `packed` 的收益和代价

收益是协议/记录偏移紧凑可控；代价是非对齐成员访问可能更慢、生成额外指令，某些架构甚至 fault。不要把所有 RAM 结构体都 packed。

### 为什么不能用 `memcmp` 比较所有普通结构体

padding 字节可能未初始化且不同；浮点存在多种表示细节；逻辑相等不一定等于每字节相同。持久化记录经明确清零/packing 后可有条件使用，但应理解前提。

### Magic 和 CRC 分别解决什么

Magic 快速识别格式/空白区域；CRC 检测内容损坏或不完整。Magic 相同不代表数据完整，CRC 正确也不代表物理测量准确。

## B.6 第 6 章：高级 C

### `volatile` 的正确用途

内存映射寄存器、被硬件/ISR 异步改变且必须真实读写的对象。它保证访问的可观察性，不保证原子、互斥、跨任务 happens-before 或多字段一致性。

### 宏与 `static inline`

宏无类型检查、可能重复求值、作用域弱。短函数优先 `static inline`；宏保留给条件编译、字符串化/连接或确有必要的编译期表达。

### 函数指针的价值

把行为作为数据保存。裸机 scheduler 不知道具体任务，只按统一签名调用 `function(context)`；这也是回调、C ops table 和 C++ 虚分派的基础。

### 中断共享 32 位变量是否一定安全

Cortex-M3 对齐 32 位读写通常单指令，但复合操作 `counter++` 是读—改—写，可能被打断。还要考虑编译器、内存排序和多执行上下文合同。用临界区或适合的原子/RTOS机制。

## B.7 第 7 章：数据结构

### 当前任务为什么用数组而不是链表

最多 8 项且经常全扫描。数组连续、无分配、最坏时间确定。链表增加指针 SRAM、跳转和所有权复杂度，没有实际收益。

### 环形队列为何 O(1)

head/tail 直接定位入队/出队位置，每次只更新固定数量字段，不搬动其余元素。

### 为什么队列需要满策略

生产者可能快于消费者。必须明确阻塞、拒绝、覆盖、丢旧、合并或扩容。当前裸机事件队列拒绝新事件并累计 dropped；UI 最新状态更适合覆盖。

### 状态和事件的区别

状态描述“现在是什么”，中间值常可覆盖；事件描述“发生过什么”，很多事件必须逐个处理。例如最新温度适合长度 1 overwrite，按钮点击通常不能任意覆盖。

## B.8 第 8 章：STM32/Cortex-M3

### 外设地址与 RAM 地址有什么本质联系

都在统一地址空间中，但芯片地址译码把外设区域的总线访问送到硬件寄存器。寄存器访问可能有副作用，因此使用设备头文件和 `volatile`。

### `.data` 为什么占 Flash 又占 SRAM

非零初值必须非易失地保存在 Flash；运行期间变量可修改，所以在 SRAM 有执行副本。启动代码负责复制。

### ISR 中直接刷新 OLED 的后果

I2C 传输慢，ISR 会长时间占用中断上下文，推迟 SysTick/其他中断，破坏 RTOS API 规则并增加嵌套栈。ISR 应只记录/通知，任务刷新。

### HAL 与寄存器是否互斥

不是。可用 HAL 初始化和普通驱动，对测量证明的热点局部使用 LL/寄存器。但同一外设的状态管理必须一致，不能随意绕过 HAL 导致句柄与硬件状态不同步。

## B.9 第 9 章：GPIO/I2C/SPI

### I2C 为什么开漏

任何设备都只能拉低，释放后由上拉变高，多个设备不会出现一边强推高、一边强拉低的硬冲突，并支持 ACK、仲裁和时钟拉伸。

### 内部上拉按钮为何按下为 0

松开时弱上拉连接到 3.3 V；按下后按钮把引脚低阻连接到 GND，低电平占优。

### 7 位地址 `0x44` 为什么 HAL 传 `0x88`

部分 HAL API 参数按 8 位地址字段位置接收，需要把 7 位地址左移一位，为最低 R/W 位留位置。要以具体 API 文档为准。

### SPI 读取为什么发送 dummy

SPI 全双工，SCK 由主机输出。主机必须发送某个字节才能产生 8 个时钟，同时 MISO 移入数据。dummy 的 MOSI 内容通常被器件忽略。

### DMA 何时值得

持续、大块、重复传输且 CPU 可并行做其他工作时。几个字节命令中，DMA 配置和完成中断成本可能更大。

## B.10 第 10 章：驱动

### 为什么快照先在局部构造

避免调用者看到一部分新、一部分旧的字段；完成后整体提交。RTOS 中队列按值复制进一步建立消息边界。

### 双 OLED 缓冲的取舍

增加 1024 B SRAM，以快速识别未变化 page/列，减少约几十毫秒级 I2C 发送。是否值得取决于 SRAM 余量、UI 变化范围和响应目标。

### W25Q64 为什么要擦除

NOR Flash 编程通常只能把 bit 从 1 改 0；要回到 1 必须按扇区擦除。页写还有 256 B 边界和 busy 时间。

### 64 KiB 日志为什么只有约 34 小时

64 KiB / 32 B = 2048 条；每分钟一条就是 2048 分钟，约 34.13 小时。

## B.11 第 11 章：裸机系统

### 周期为什么按旧 deadline 加 period

这样任务迟 1 ms 执行不会让以后每轮都多迟 1 ms，减少累计漂移。落后太多时跳过历史周期，避免追赶风暴。

### 为什么 `U < 100%` 还可能卡顿

平均利用率不能限制最长不可抢占段。一个 30 ms 阻塞事务足以让 2 ms 输入任务延迟 30 ms，即使一秒平均 CPU 很空。

### 当前 event bus 为什么不能 ISR post

head/tail/count 的复合更新无临界区。若 ISR 与主循环交错，计数和索引可能不一致。当前设计让 ISR 更新小型 encoder 状态，任务再发布事件。

### 8 个任务是否应使用最小堆

通常不应。线性扫描最多 8 项，固定成本极小、代码直观。堆增加维护和错误面，收益不可测。

## B.12 第 12 章：FreeRTOS

### 为什么每个任务要独立栈

任务可在函数调用链中阻塞，随后从同一点恢复；其局部变量、返回信息和保存寄存器必须独立保留。

### overwrite queue 适合什么

长度 1 的最新状态，如 UI snapshot/settings。它不适合每条都必须持久化的日志事件。

### mutex 比 binary semaphore 多什么

互斥锁表达所有权，并支持优先级继承，缓解优先级反转。它不能从 ISR 使用，也不能自动防止死锁/忘记释放。

### 独立 storage 任务忙等为什么仍不好

它不一定冻结高优先级任务，但持续占 CPU，推迟低优先级任务并增加功耗。可在轮询间阻塞，或使用分阶段状态机。

### `volatile s_flash_ready` 为什么不完整

它只确保真实访问，不表达消息顺序、错误详情、多字段一致性或任务所有权。队列/通知/锁或单一所有者模型更清楚。

## B.13 第 13 章：C++ 类与 RAII

### 类一定比 C struct 大吗

不一定。只有普通数据成员的类可与等价 struct 相同；成员函数不存进每个对象。virtual 通常引入 vptr，空类/继承/对齐规则另有影响，最终看 `sizeof`/ABI。

### 构造函数为什么不建议做硬件 IO

构造函数没有普通返回值表达 NACK/timeout；全局构造可能在时钟/HAL 初始化前运行。构造只建立对象内存不变量，`init()` 显式访问硬件更清楚。

### RAII 为什么适合 CS

构造拉低、析构拉高，任何提前 return 都自动恢复事务边界；guard 删除拷贝避免重复释放。

### 为什么默认避免 `new/delete`

固定对象数量不需要动态图，静态分配更容易确定 SRAM、时间、失败和所有权。不是语言禁止，而是当前收益不足。

## B.14 第 14 章：继承与模板

### 何时使用公有继承

存在真正可替换的 is-a 合同，调用者需要统一对待不同实现。拥有传感器/显示应使用组合，不是多重继承。

### 虚调用典型成本

对象通常多一个 vptr，类型有 vtable，调用经间接函数指针，可能阻碍内联。标准不规定具体布局，目标编译器可能去虚化。

### 模板为何可能变大

每个 `T,N` 组合可能实例化一份成员机器码。也可能因为强内联/常量传播更小。查看 map/反汇编，不能统一下结论。

### C ops table 与 vtable 的联系

都把操作函数地址放在表中并通过对象/上下文间接调用。C++ 由语言检查 override、this 和析构；C 由程序员手工维护布局和转换。

## B.15 第 15 章：嵌入式 C++

### 为什么建立独立 target

ARMCC5 现代 C++ 支持有限，运行库/异常/RTTI/启动初始化也可能改变。独立 target 保留 C 基线并能逐步测量每项成本。

### 成员函数如何交给 C scheduler/FreeRTOS

用静态 trampoline 接收 `void *context`，cast 回对象后调用普通成员函数。对象必须比任务/调度项活得久。

### “零成本”怎样证明

同优化和配置下比较 map、反汇编、栈和 GPIO/DWT 时序。强类型/普通 inline 类通常可消除，但虚调用、类型擦除和标准库需分别量化。

## B.16 第 16 章：编译链接 ABI

### undefined 与 multiple definition

undefined：调用者引用的外部符号没有定义被链接进来；multiple：两个对象提供同名强定义。

### weak callback 拼错为何仍能链接

库的 weak 默认实现仍满足符号。你的错误名字只是另一个无人调用的函数。查 map/断点可确认实际绑定。

### `extern "C"` 做什么

给声明/定义 C 语言链接，避免 C++ name mangling，使 C 启动/HAL 能按约定符号找到函数。它不自动让任意 C++ 类型变成 C ABI 安全。

### packed struct 为什么仍不等于永久格式

还绑定端序、字段定义、编译器扩展、版本和浮点表示。手工序列化最明确。

## B.17 第 17 章：调试与可靠性

### 第二缓冲是优化还是浪费

两者都可能。它用 1024 B SRAM 换少量比较和更少 I2C 传输。若 SRAM 紧张且 dirty 标记可靠，可换成脏范围；若 SRAM 有余量，双缓冲更稳。

### 看门狗为什么不能无条件喂

无条件喂只能证明“喂狗代码还在运行”，不能证明 sensor/UI/storage 等关键功能健康。应汇总各关键任务 heartbeat 后喂。

### HardFault 为什么先取 stacked PC

PC 指向 fault 时的执行位置，结合 CFSR/BFAR/MMFAR 和 map/反汇编能定位非法指令/访问。只看当前 HardFault 循环 call stack 往往只看到处理函数。

### O2 锁死首查

数组越界、未初始化变量、悬空指针、别名违规、有符号溢出、错误 volatile/同步、栈布局敏感内存破坏、依赖未规定求值顺序。

## B.18 开放设计题如何自评

一个合格答案至少覆盖：

1. **接口**：输入、输出、错误；
2. **状态**：由谁拥有，生命周期；
3. **时间**：是否阻塞、超时、最坏执行；
4. **内存**：静态/栈/队列容量；
5. **并发**：ISR/任务/锁/原子；
6. **持久化**：版本、CRC、掉电；
7. **失败**：降级、重试、恢复；
8. **验证**：单元测试、波形、Map、长测。

如果答案只有“调用某个 HAL 函数”或“加一个 mutex”，还没有完成系统设计。
