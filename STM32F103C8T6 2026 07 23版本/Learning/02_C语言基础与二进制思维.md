# 02　C 语言基础与二进制思维

## 本章目标

你将掌握变量、类型、表达式、控制流和位运算，并理解它们在 STM32 上对应的真实数据。完成后应能独立编写一个读取状态、更新计数并输出结果的小程序。

## 1. 程序处理的是“带解释的比特”

内存本身只保存 0 和 1。类型告诉编译器这些比特应怎样解释：

- 是无符号整数还是有符号整数；
- 占多少字节；
- 是否按 IEEE 754 浮点格式解释；
- 做加法时使用整数指令还是浮点运算库；
- 读取多少个字节以及怎样扩展。

同一组比特 `11111111`：

- 解释为 `uint8_t` 是 255；
- 解释为 `int8_t`，在常见二进制补码机器上是 -1；
- 解释为字符可能对应一个扩展字符值。

因此，“变量等于什么”包含两个问题：比特是什么，类型怎样解释。

## 2. 为什么嵌入式项目常用 `stdint.h`

C 的 `int` 至少 16 位，但标准没有要求所有平台都固定为 32 位。嵌入式协议和寄存器必须精确知道宽度，所以项目使用：

| 类型 | 位数 | 常见范围 |
|---|---:|---:|
| `uint8_t` | 8 | 0～255 |
| `int8_t` | 8 | -128～127 |
| `uint16_t` | 16 | 0～65535 |
| `int16_t` | 16 | -32768～32767 |
| `uint32_t` | 32 | 0～4294967295 |
| `int32_t` | 32 | -2147483648～2147483647 |

在项目中：

```c
typedef struct {
    uint16_t year;
    uint8_t month;
    uint8_t day;
    uint8_t weekday;
    uint8_t hour;
    uint8_t minute;
    uint8_t second;
} app_datetime_t;
```

年份需要超过 255，使用 16 位；月、日、时、分、秒都落在 0～255，使用 8 位即可。

### 2.1 `U` 和 `UL` 后缀

项目中经常看到：

```c
#define APP_LOG_PERIOD_MS    60000U
#define APP_LOG_REGION_START 0x00010000UL
```

- `U` 表示无符号整数常量；
- `L` 表示至少为 `long`；
- `UL` 表示 `unsigned long`。

后缀减少有符号/无符号混合运算造成的警告和边界错误。寄存器、地址、时间计数通常天然适合无符号类型。

## 3. 二进制与十六进制

一个十六进制数字正好表示 4 个二进制位：

```text
0x0 = 0000
0x1 = 0001
0xA = 1010
0xF = 1111
0x23 = 0010 0011
```

所以寄存器、地址和掩码通常写成十六进制。`0x68` 比十进制 104 更容易与设备手册中的地址对应。

### 3.1 位编号

一个 8 位整数通常编号为 bit7～bit0：

```text
bit:   7 6 5 4 3 2 1 0
value: 0 0 0 1 0 1 0 1
```

每一位的权重依次是 `128,64,32,16,8,4,2,1`。

## 4. 位运算

| 运算符 | 名称 | 用途 |
|---|---|---|
| `&` | 按位与 | 读取/保留指定比特 |
| `|` | 按位或 | 设置指定比特 |
| `^` | 按位异或 | 翻转指定比特 |
| `~` | 按位取反 | 生成反掩码 |
| `<<` | 左移 | 将 1 移到目标位或扩大 2 的幂 |
| `>>` | 右移 | 提取高位或除以 2 的幂 |

项目在 `app_types.h` 中定义有效标志：

```c
enum {
    APP_VALID_RTC    = 1U << 0,
    APP_VALID_SHT30  = 1U << 1,
    APP_VALID_BMP280 = 1U << 2,
    APP_VALID_BH1750 = 1U << 3,
    APP_VALID_FLASH  = 1U << 4,
    APP_VALID_OLED   = 1U << 5
};
```

如果 RTC、SHT30 和 OLED 有效：

```c
uint8_t valid = APP_VALID_RTC | APP_VALID_SHT30 | APP_VALID_OLED;
```

二进制结果为：

```text
0010 0011 = 0x23
```

检查 SHT30：

```c
if ((valid & APP_VALID_SHT30) != 0U) {
    /* SHT30 数据有效 */
}
```

清除 SHT30 标志：

```c
valid &= (uint8_t)~APP_VALID_SHT30;
```

切换某一标志：

```c
valid ^= APP_VALID_SHT30;
```

### 4.1 位运算与逻辑运算不能混淆

```c
a & b   /* 每一位进行 AND */
a && b  /* 判断 a、b 是否为真，结果只有 0 或 1 */
```

读取标志使用 `&`；组合条件使用 `&&`。

## 5. 变量、初始化和赋值

```c
uint32_t sequence = 0U;   /* 定义并初始化 */
sequence = sequence + 1U; /* 赋值 */
++sequence;               /* 自增 */
```

未初始化的局部自动变量值不确定：

```c
void bad_example(void)
{
    uint32_t count;
    count++; /* 错误：读取不确定值 */
}
```

全局和 `static` 变量在 C 运行时启动时会清零，但依赖隐式清零会降低阅读清晰度。关键状态仍应在初始化函数中显式设置。

## 6. 有符号、无符号和溢出

无符号整数按模 `2^N` 回绕。`uint8_t` 的 255 加 1 得到 0：

```c
uint8_t value = 255U;
++value; /* 0 */
```

这不是随机错误，而是无符号运算规则。项目利用 32 位无符号时间自然回绕：

```c
static bool elapsed(uint32_t now, uint32_t since, uint32_t duration)
{
    return (uint32_t)(now - since) >= duration;
}
```

即使 `now` 在约 49.7 天后回到 0，只要比较间隔小于半个 32 位范围，减法仍能给出正确经过时间。

有符号溢出在 C 中属于未定义行为，不能依赖它回绕。涉及硬件计数、时间戳和位掩码时，优先明确使用无符号类型。

## 7. 整数提升与类型转换

小于 `int` 的类型在表达式中常先提升为 `int`：

```c
uint8_t a = 200U;
uint8_t b = 100U;
uint16_t sum = a + b; /* a、b 通常先提升为 int，结果 300 */
```

但最后赋给较小类型会截断：

```c
uint8_t wrong = a + b; /* 300 模 256，得到 44 */
```

移位前先转换到足够宽类型：

```c
uint32_t value = ((uint32_t)bytes[0] << 16U) |
                 ((uint32_t)bytes[1] << 8U)  |
                 (uint32_t)bytes[2];
```

W25Q64 JEDEC ID 正是这样由 3 个字节组合成 24 位值。

## 8. 浮点数

项目使用 `float` 表示温度、湿度、气压和照度：

```c
float temperature_c;
float humidity_rh;
```

STM32F103 的 Cortex-M3 没有硬件浮点单元，浮点运算由软件完成。传感器每秒计算一次时通常可以接受，但不适合在高频中断中大量运算。

浮点数不能用 `==` 判断计算结果是否“完全相等”：

```c
float difference = measured - expected;
if (difference < 0.0f) {
    difference = -difference;
}
if (difference < 0.01f) {
    /* 认为足够接近 */
}
```

写入 Flash 时项目把部分浮点值乘 100 并转换成整数，例如 25.37°C 保存为 2537。这称为定点缩放，便于节省空间并获得稳定格式。

## 9. 控制流

### 9.1 `if/else`

适合范围判断和组合条件：

```c
if (!flash_ready) {
    show_error();
} else if (record_count == 0U) {
    show_empty();
} else {
    show_count(record_count);
}
```

### 9.2 `switch`

适合枚举状态：

```c
switch (event.type) {
case APP_EVENT_ENCODER_CLOCKWISE:
    /* 处理顺时针 */
    break;
case APP_EVENT_ENCODER_CLICK:
    /* 处理短按 */
    break;
default:
    break;
}
```

忘记 `break` 会继续执行下一个 `case`。有意贯穿时应添加明确注释。

### 9.3 `for` 与 `while`

`for` 适合明确计数：

```c
for (uint8_t page = 0U; page < 8U; ++page) {
    update_page(page);
}
```

`while` 适合条件驱动：

```c
while (event_bus_pop(&event)) {
    dispatch(event);
}
```

MCU 主循环常写为：

```c
for (;;) {
    run_tasks();
}
```

`for(;;)` 条件永远为真。

## 10. 一个完整可运行例子

```c
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>

enum {
    SENSOR_TEMP = 1U << 0,
    SENSOR_LIGHT = 1U << 1
};

int main(void)
{
    uint8_t valid = 0U;
    uint32_t sample_count = 0U;

    valid |= SENSOR_TEMP;
    valid |= SENSOR_LIGHT;

    for (uint8_t i = 0U; i < 3U; ++i) {
        ++sample_count;
        printf("sample=%lu temp=%s light=%s\n",
               (unsigned long)sample_count,
               (valid & SENSOR_TEMP) ? "OK" : "ERR",
               (valid & SENSOR_LIGHT) ? "OK" : "ERR");
    }

    valid &= (uint8_t)~SENSOR_LIGHT;
    printf("after fault: mask=0x%02X\n", (unsigned int)valid);
    return 0;
}
```

预期输出：

```text
sample=1 temp=OK light=OK
sample=2 temp=OK light=OK
sample=3 temp=OK light=OK
after fault: mask=0x01
```

## 11. 常见错误

- 把 `=` 写成 `==`，或反过来；
- 把 `&` 写成 `&&`；
- 对无符号变量判断 `< 0`；
- 将 300 存入 `uint8_t`；
- 右移有符号负数并假定所有编译器行为一致；
- 忘记为常量添加合适的 `U`；
- 把毫秒、秒、摄氏度等不同单位直接相加；
- 在高频中断中进行大量 `float` 和 `printf`。
