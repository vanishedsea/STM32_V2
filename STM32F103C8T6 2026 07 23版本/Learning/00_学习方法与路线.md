# 00　学习方法、实验规则与路线

## 1. 这套教材适合怎样学习

推荐节奏是每天 60～90 分钟，每周 4～5 天。一次学习分成四段：

1. **阅读 20～30 分钟**：理解本节概念，并把不懂的名词记下来。
2. **手写 15 分钟**：不复制代码，自己敲一遍最小例子。
3. **实验 20～30 分钟**：运行 PC 示例或修改 STM32 的一个参数。
4. **复盘 10 分钟**：写下“现象、原因、证据、结论”。

连续看两小时并不等于学会。真正的掌握标准是：离开教材后，你能用自己的语言解释，并能通过实验验证。

## 2. 三层学习法

每个知识点都要经过三层。

### 第一层：会使用

例如，知道如何声明数组、调用函数、创建任务。这一层解决“代码能不能写出来”。

### 第二层：会解释

例如，能解释数组为何连续存储，函数调用为何需要栈，FreeRTOS 队列为何要复制数据。这一层解决“为什么这样工作”。

### 第三层：会取舍

例如，能判断何时使用固定数组、环形队列、链表、虚函数或模板。这一层解决“面对新项目应该怎么设计”。

只完成第一层时，换一个项目就容易失去方向。这套教材会把第二、第三层作为重点。

## 3. 实验安全规则

### 3.1 一次只改一个变量

如果同时修改 I2C 频率、任务优先级、OLED 刷新逻辑和中断配置，出现异常时无法确定原因。每次实验应记录：

```text
实验目标：观察 UI 周期对动画的影响
修改文件：App/Inc/app_config.h
修改前：APP_UI_PERIOD_MS = 20U
修改后：APP_UI_PERIOD_MS = 100U
预期：动画明显变慢，传感器采样周期不变
结果：
结论：
```

### 3.2 先编译，再接硬件验证

推荐顺序：

```text
阅读修改 → 保存 → F7 编译 → 检查 0 Error/0 Warning
→ 检查接线与供电 → F8 下载 → 观察 → 记录
```

### 3.3 保留稳定基线

当前 `01_BareMetal_Keil` 和 `02_FreeRTOS_Keil` 是稳定参考。学习 C/C++ 的纯语法实验放到 `Learning/Examples`。需要大幅重构 STM32 时，先复制成学习实验工程，避免破坏日常可烧录版本。

### 3.4 不把硬件异常误判成语法问题

常见硬件异常包括：

- 模块没有共地；
- SDA/SCL 上拉过强或被拉到 5V；
- W25Q64 供电不稳定；
- ST-Link 只接了两根信号线而没有共地；
- 长杜邦线导致 400 kHz I2C 波形变差；
- 旋转编码器引脚丝印与实际顺序不同。

程序编译成功只能证明语法和链接基本正确，不能证明接线正确。

## 4. 推荐进度

| 阶段 | 章节 | 建议时间 | 里程碑 |
|---|---|---:|---|
| A | 01～03 | 3～4 周 | 能写多文件 C 程序 |
| B | 04～07 | 5～7 周 | 掌握指针、内存和数据结构 |
| C | 08～10 | 5～6 周 | 能阅读手册并理解驱动 |
| D | 11～12 | 4～5 周 | 能设计裸机/RTOS 架构 |
| E | 13～15 | 6～8 周 | 能写受控资源的嵌入式 C++ |
| F | 16～18 | 5 周以上 | 能分析底层、性能和可靠性 |

进度不是考试倒计时。如果第 4 章的指针没有理解，就不急着进入 C++。指针、对象、虚函数和 RTOS 栈最终都落在内存上。

## 6. 如何向我提问

高质量问题应包含证据。建议使用下面格式：

```text
我正在学习：04_指针数组字符串与内存
目标：理解 uint8_t *buffer
我认为它表示：……
不理解的位置：ssd1306_update() 中 memcpy 的第三个参数
编译结果：0 Error, 0 Warning
运行现象：局部刷新后右侧图像没有更新
我已经检查：……
```

这样我能直接判断是语法、内存、算法、外设协议还是硬件问题。

## 7. 阶段检查方法

每完成一个阶段，都做一次“脱离教材”练习：

- 不看原代码，写一个固定容量环形队列；
- 不看接线文档，说出 I2C 和 SPI 的信号方向；
- 不看 `main.c`，画出裸机任务关系；
- 不看 FreeRTOS API，解释 Queue 与 Mutex 的用途；
- 不看 C++ 章节，解释组合、继承和多态；
- 打开 Keil map/反汇编，用证据说明一个变量位于 RAM 还是 Flash。

答不出来并不代表失败，它指出下一次复习的精确位置。
