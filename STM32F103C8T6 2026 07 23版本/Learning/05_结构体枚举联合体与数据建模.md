# 05　结构体、枚举、联合体与数据建模

## 本章目标

程序设计的核心不是语法数量，而是如何把现实问题转换成清晰的数据模型。本章使用传感器快照、事件、UI 状态和 Flash 记录讲解结构体、枚举、联合体、对齐、字节序和序列化。

## 1. 为什么需要结构体

如果把一次环境采样拆成许多无关变量：

```c
float temperature;
float humidity;
float pressure;
float lux;
uint32_t sequence;
```

函数参数、队列和存储接口会非常混乱。结构体把相关字段组合成一个概念：

```c
typedef struct {
    uint32_t sequence;
    uint8_t valid_mask;
    app_datetime_t time;
    float temperature_c;
    float humidity_rh;
    float bmp_temperature_c;
    float pressure_pa;
    float illuminance_lux;
} app_snapshot_t;
```

这代表“一次完整快照”，而不是八个碰巧同时存在的变量。

## 2. 定义类型与创建对象

```c
typedef struct {
    uint16_t year;
    uint8_t month;
    uint8_t day;
} date_t;

date_t today = {2026U, 7U, 17U};
```

访问成员：

```c
today.year = 2027U;
```

通过指针访问：

```c
date_t *date = &today;
date->month = 8U;
```

`date->month` 等价于 `(*date).month`。

## 3. 初始化

顺序初始化依赖字段顺序：

```c
date_t date = {2026U, 7U, 17U};
```

指定成员初始化（C99）：

```c
date_t date = {
    .year = 2026U,
    .month = 7U,
    .day = 17U
};
```

指定初始化更适合字段较多的结构体，能减少顺序变化带来的错误。ARMCC5 的具体语言模式需要确认 C99 设置；当前项目已按 C99 编译。

## 4. 结构体复制和比较

结构体可按值复制：

```c
app_snapshot_t a;
app_snapshot_t b = a;
```

这会复制所有成员。FreeRTOS Queue 发送结构体时也会把指定字节复制到队列内部。

C 不能直接用 `==` 比较两个结构体。也不应随意用 `memcmp` 判断“逻辑相等”，因为填充字节可能包含不确定值，浮点值也有特殊规则。应逐成员比较或写专用函数。

## 5. 对齐和填充

处理器通常更高效地从自然对齐地址访问多字节数据。编译器可能在字段之间加入填充：

```c
typedef struct {
    uint8_t flag;     /* offset 0 */
    uint32_t count;   /* 可能放在 offset 4 */
} example_t;
```

这个结构体可能不是 5 字节，而是 8 字节：

```text
offset 0: flag
offset 1～3: padding
offset 4～7: count
```

使用：

```c
sizeof(example_t)
offsetof(example_t, count)
```

验证实际布局。不要只靠目测猜测。

### 5.1 调整字段顺序

```c
typedef struct {
    uint32_t count;
    uint8_t flag;
} better_t;
```

仍可能因末尾对齐为 8 字节，但多个小字段集中放置通常能减少内部填充。

## 6. `packed`

存储记录必须具有固定字节格式，项目使用：

```c
typedef struct __attribute__((packed)) {
    uint32_t magic;
    uint32_t sequence;
    /* ... */
    uint32_t crc32;
} log_record_t;
```

并在编译期验证：

```c
typedef char log_record_size_must_be_32[
    (sizeof(log_record_t) == 32U) ? 1 : -1];
```

`packed` 取消正常填充，使格式稳定，但也可能产生未对齐访问。使用场景应限于协议/存储布局，业务运行结构体一般保持自然对齐。

更严格的序列化方案是显式写入字节数组，不直接把结构体原样保存。它能跨编译器、端序和版本保持可控。

## 7. 字节序

一个 32 位值 `0x12345678` 有 4 个字节：`12 34 56 78`。

- 大端：低地址存 `12`；
- 小端：低地址存 `78`。

Cortex-M3 常用小端模式。I2C/SPI 设备协议经常规定大端传输，所以驱动必须按手册组合：

```c
uint16_t value = ((uint16_t)data[0] << 8U) | data[1];
```

不能假定“把两个字节地址转换成 `uint16_t *`”就得到协议值。

## 8. 枚举

枚举给有限状态命名：

```c
typedef enum {
    APP_EVENT_NONE = 0,
    APP_EVENT_NEW_SNAPSHOT,
    APP_EVENT_STORAGE_ERROR,
    APP_EVENT_ENCODER_CLOCKWISE,
    APP_EVENT_ENCODER_COUNTERCLOCKWISE,
    APP_EVENT_ENCODER_CLICK,
    APP_EVENT_ENCODER_LONG_PRESS
} app_event_type_t;
```

优点：

- 比裸数字可读；
- `switch` 能列出所有状态；
- 调试器能显示名字；
- 接口表达“只能取这些值”。

### 8.1 枚举的大小

C 标准不保证枚举一定为 1 字节。编译器通常选择可表示所有枚举值的整数类型。写入协议或 Flash 时，不要直接依赖枚举的编译器大小；存储格式中使用明确宽度字段并显式转换。

## 9. 事件模型

```c
typedef struct {
    app_event_type_t type;
    uint32_t value;
} app_event_t;
```

它将事件种类和一个通用参数放在一起。优点是队列元素固定；限制是不同事件只有一个 32 位参数。

扩展方式之一是使用联合体：

```c
typedef struct {
    app_event_type_t type;
    union {
        uint32_t sequence;
        int32_t encoder_delta;
        uint32_t error_code;
    } data;
} app_event_t;
```

联合体成员共享同一块内存，大小取最大成员。`type` 决定当前应读取哪个成员。

## 10. 联合体

```c
union raw_value {
    uint32_t u32;
    float f32;
    uint8_t bytes[4];
};
```

所有成员覆盖同一存储空间。联合体适合：

- 不同类型事件载荷；
- 节省互斥状态数据的空间；
- 硬件寄存器不同视图（需谨慎）；
- 变体类型。

不要把“写一个成员、读另一个成员”当作完全可移植的类型转换方式。协议转换优先使用 `memcpy` 或显式字节操作。

## 11. 位域

```c
typedef struct {
    unsigned ready : 1;
    unsigned error : 1;
    unsigned mode  : 2;
} status_bits_t;
```

位域看起来适合寄存器，但位顺序、分配单元和对齐具有实现相关性。跨编译器协议、Flash 格式和严格硬件寄存器映射更适合显式掩码：

```c
#define STATUS_READY (1U << 0)
```

位域适合编译器和平台完全受控、布局要求经过验证的场景。

## 12. 数据模型设计原则

### 12.1 名字带单位

```c
float pressure_pa;
uint32_t timeout_ms;
```

比 `pressure`、`timeout` 更安全。单位错误是嵌入式系统常见问题。

### 12.2 区分原始数据和工程量

```c
int32_t raw_temperature;
float temperature_c;
```

原始 ADC/寄存器值与换算结果不是同一概念。

### 12.3 有效性单独表达

传感器读失败时，0°C 可能是合法数据，不能用 0 表示错误。项目使用 `valid_mask`，也可使用结果结构体：

```c
typedef struct {
    bool valid;
    float value;
} float_measurement_t;
```

### 12.4 存储格式要有版本

设置记录包含 magic、version 和 CRC。以后增加字段时，可根据版本选择解析方式，避免新固件错误解释旧数据。

## 13. 序列化与 CRC

CRC 应覆盖完全确定的字节。项目使用：

```c
record->crc32 = crc32_compute(record,
                              offsetof(log_record_t, crc32));
```

也就是从记录开头计算到 `crc32` 成员之前。读取时重新计算并比较。

关键要求：

- 计算前所有被覆盖字节必须初始化；
- 写入和读取使用相同格式；
- 格式改变应更新版本；
- 不要让未初始化填充字节进入 CRC。

## 14. C 与 C++ 数据建模预览

C 将数据与操作分开：

```c
typedef struct {
    float temperature;
} sensor_t;

bool sensor_read(sensor_t *sensor);
```

C++ 可以把操作放入类：

```cpp
class Sensor {
public:
    bool read();
    float temperature() const;
private:
    float temperature_{};
};
```

两者都能封装。区别在语言提供的类型系统、访问控制、构造析构和多态机制。第 13～15 章详细比较。

## 15. 练习

1. 手算 `app_datetime_t` 在当前编译器中可能的大小，再用 `sizeof` 验证。
2. 设计一个含温度、湿度、有效标志和时间戳的结构体。
3. 将 `app_event_t` 扩展为带联合体载荷，保证事件意义清晰。
4. 解释为什么存储格式不直接使用 C 枚举大小。
5. 设计一个 16 字节设置记录，包含 magic、version、theme、beep、sequence 和 CRC；如果放不下，明确说明取舍。
6. 写出从大端 3 字节恢复 24 位值的代码。
7. 解释 `packed` 为什么既有价值又有风险。

检查点：你能为一个新模块设计运行时结构体、持久化记录和对应的版本/有效性策略。
