# 07　数据结构与算法在项目中的应用

## 本章目标

数据结构是“数据怎样组织”，算法是“怎样操作这些数据”。嵌入式环境还要考虑：固定 RAM、可预测执行时间、无动态分配和中断并发。

本章完成后，你应能实现固定容量环形队列，并能解释为什么项目在不同位置选择数组、队列、状态机和环形 Flash。

## 1. 先确定操作，再选结构

不要因为学过链表就到处用链表。选择前回答：

- 最大元素数量是否已知？
- 是否要求随机访问？
- 是否频繁在中间插入？
- 是否必须保持顺序？
- 操作是否发生在中断中？
- 最坏运行时间能否接受？
- 能否使用动态内存？
- 数据是否需要持久化？

项目中的选择：

| 问题 | 结构 |
|---|---|
| 最多 8 个固定周期任务 | 固定数组 |
| 最多 16 个待处理事件 | 环形队列 |
| 4 个数据页、8 个菜单项 | 小型数组/枚举 |
| OLED 128×64 像素 | 连续帧缓冲区 |
| W25Q64 反复覆盖日志 | 按扇区的环形记录区 |
| UI 动画和 Flash 操作 | 有限状态机 |

## 2. 复杂度

大 O 表示输入规模增长时的数量级：

| 复杂度 | 示例 |
|---|---|
| O(1) | 数组按下标访问、环形队列入队 |
| O(log n) | 二分查找、平衡树查找 |
| O(n) | 顺序扫描、链表查找 |
| O(n log n) | 高效通用排序 |
| O(n²) | 双重全组合比较 |

嵌入式更关心最坏情况，而不仅是平均情况。16 项线性扫描完全可以接受；在高频中断中扫描几万个元素则不可接受。

## 3. 固定数组

优点：

- 连续内存；
- O(1) 随机访问；
- 无分配失败；
- 缓存/总线访问友好；
- 容量和 RAM 占用编译期可知。

缺点：

- 容量固定；
- 中间插入/删除需要移动；
- 容量预留可能浪费少量 RAM。

裸机调度器最多 8 项：

```c
#define SCHEDULER_MAX_TASKS 8U
static scheduler_entry_t s_tasks[SCHEDULER_MAX_TASKS];
```

任务注册频率很低，运行时每 1 ms 扫描 8 项，简单且可预测。为了把 O(8) 优化成复杂堆结构没有必要。

## 4. 顺序表

顺序表是在数组上记录有效长度：

```c
#define LIST_CAPACITY 8U

typedef struct {
    int32_t items[LIST_CAPACITY];
    size_t count;
} int_list_t;
```

尾部添加：

```c
bool int_list_push(int_list_t *list, int32_t value)
{
    if ((list == NULL) || (list->count >= LIST_CAPACITY)) {
        return false;
    }
    list->items[list->count++] = value;
    return true;
}
```

删除中间项需要把后续元素左移，O(n)。小容量配置列表仍很合适。

## 5. 链表

```c
typedef struct node {
    int32_t value;
    struct node *next;
} node_t;
```

优点：已知节点地址时插入/删除 O(1)，无需移动其他元素。缺点：

- 每个节点多一个指针；
- 查找第 n 项是 O(n)；
- 非连续内存；
- 通常需要动态分配或固定节点池；
- 指针损坏可能破坏整个链；
- 中断并发操作更复杂。

当前项目容量小且固定，所以没有必要用链表。学习链表是为了理解指针、所有权和动态结构，不代表它适合所有 MCU 队列。

## 6. 栈

数据结构中的栈遵循 LIFO（后进先出）：

```c
#define STACK_CAPACITY 8U

typedef struct {
    int32_t data[STACK_CAPACITY];
    size_t top;
} stack_t;
```

压栈：`data[top++] = value`；弹栈：`value = data[--top]`。

用途：

- 表达式解析；
- 深度优先遍历；
- 菜单返回路径；
- 撤销操作。

它与“函数调用栈”不是同一个具体对象，但遵循类似后进先出思想。

## 7. 普通队列

FIFO（先进先出）适合事件和消息。简单数组队列如果每次出队都移动元素，会产生 O(n) 开销。环形队列避免移动。

## 8. 环形队列完整实现

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

#define QUEUE_CAPACITY 8U

typedef struct {
    int32_t data[QUEUE_CAPACITY];
    size_t head;  /* 下一个出队位置 */
    size_t tail;  /* 下一个入队位置 */
    size_t count; /* 当前元素数量 */
} int_queue_t;

void int_queue_init(int_queue_t *queue)
{
    if (queue == NULL) {
        return;
    }
    queue->head = 0U;
    queue->tail = 0U;
    queue->count = 0U;
}

bool int_queue_push(int_queue_t *queue, int32_t value)
{
    if ((queue == NULL) || (queue->count >= QUEUE_CAPACITY)) {
        return false;
    }
    queue->data[queue->tail] = value;
    queue->tail = (queue->tail + 1U) % QUEUE_CAPACITY;
    ++queue->count;
    return true;
}

bool int_queue_pop(int_queue_t *queue, int32_t *value)
{
    if ((queue == NULL) || (value == NULL) || (queue->count == 0U)) {
        return false;
    }
    *value = queue->data[queue->head];
    queue->head = (queue->head + 1U) % QUEUE_CAPACITY;
    --queue->count;
    return true;
}
```

### 8.1 为什么需要 `count`

如果只保存 head/tail，`head == tail` 既可能表示空，也可能表示满。解决方案：

- 额外保存 `count`；
- 永远空出一个槽位；
- 额外保存 full 标志。

当前事件总线使用 `count`，实现直观。

### 8.2 满队列策略

可以：

- 拒绝新事件并计数；
- 覆盖最旧事件；
- 阻塞等待空间（RTOS 任务可用）；
- 按优先级丢弃；
- 扩容（固定 MCU 系统一般不做）。

项目事件总线拒绝并增加 `s_dropped`；FreeRTOS UI 队列长度为 1，使用覆盖写，始终保留最新快照。这是两个不同语义。

## 9. 单生产者/单消费者并发

如果中断入队、主循环出队，需要考虑共享 head/tail/count 是否原子。8 位值在 Cortex-M3 上单次访问通常原子，但多个字段组合操作仍可能交错。

策略：

- 在很短入队/出队操作周围使用临界区；
- 设计严格单生产者单消费者无锁队列并证明内存顺序；
- 中断只累计简单值，任务再进入普通队列；
- FreeRTOS 中使用 FromISR API。

当前裸机编码器中断不直接写普通事件队列，而是累计 detent，任务再发布事件，降低并发复杂度。

## 10. 双端队列与优先队列

双端队列允许两端插入/删除。优先队列按优先级取元素，常用二叉堆实现。

裸机调度器当前扫描 8 项任务，复杂度 O(8)。如果扩展到上百个一次性定时器，可使用按 deadline 排序的最小堆，让取最近任务 O(1)、插入 O(log n)。但结构复杂度和调试成本也上升。

## 11. 树与菜单

当前菜单只有两页固定项目，数组足够。若形成多级设置菜单，可以建树：

```c
typedef struct menu_item menu_item_t;

struct menu_item {
    const char *label;
    void (*action)(void *context);
    void *context;
    const menu_item_t *children;
    size_t child_count;
};
```

每个节点可包含子项。遍历时需要保存当前节点和返回路径。固定菜单可全部声明为 `static const`，放入只读区域。

## 12. 哈希表

哈希表将键映射到桶，平均查找 O(1)。它适合大量动态键值，例如命令名、对象 ID。当前设备地址和菜单项数量很小，线性数组更简单。

嵌入式哈希表需要考虑：

- 固定桶数量；
- 冲突策略；
- 最坏情况退化；
- 字符串存储；
- 是否允许删除。

## 13. 查找与排序

### 13.1 线性查找

```c
for (size_t i = 0U; i < count; ++i) {
    if (items[i] == target) {
        return i;
    }
}
```

O(n)，适合小数组和未排序数据。

### 13.2 二分查找

要求数组有序，O(log n)。循环边界容易出错，应测试空数组、单元素、最小值、最大值和不存在值。

### 13.3 排序

小型固定数组可用插入排序：实现小、对近乎有序数据有效。通用大数据可学习快速排序/归并排序，但递归深度和临时内存要评估。

传感器项目几乎不需要运行时排序，说明“会算法”也包括知道什么时候不使用。

## 14. 状态机也是数据结构

状态机由：

- 状态集合；
- 输入事件；
- 转移规则；
- 状态数据；
- 动作。

Flash 后台服务的简化状态：

```text
IDLE → WAIT_ERASE → WAIT_PROGRAM → IDLE
```

它把“等待硬件忙完”编码为数据，而不是在函数里死循环。这使主循环可以继续刷新 UI 和读取输入。

## 15. 环形 Flash 日志

W25Q64 日志区 64 KiB，每条 32 字节：

```text
65536 / 32 = 2048 条
```

每个 4 KiB 扇区：

```text
4096 / 32 = 128 条
```

写到末尾后回到开头，覆盖前先按扇区擦除。这是持久化环形缓冲，但擦除粒度大于记录粒度，因此运行时有效记录数会在扇区覆盖时减少再逐渐增加。

## 16. 固定内存池

需要动态数量对象但又不想使用通用堆，可预留节点池：

```c
#define NODE_POOL_SIZE 16U

typedef struct node {
    struct node *next;
    bool used;
    uint32_t value;
} node_t;

static node_t s_pool[NODE_POOL_SIZE];
```

分配时扫描 `used == false`，释放时清除。优点：

- 无外部碎片；
- 最大内存固定；
- 可检测耗尽；
- 行为可分析。

更高效实现可维护空闲链表。

## 17. C++ 数据结构预览

在 PC 上会学习 `std::array`、`std::vector`、`std::list`、`std::deque`、`std::queue`、`std::map` 和算法库。嵌入式中选择标准容器前要检查：

- 是否动态分配；
- 异常策略；
- 代码体积；
- 最坏延迟；
- 当前 ARMCC5 的标准库能力。

第 14～15 章会实现 `FixedRingBuffer<T, N>`，在编译期确定容量且不使用堆。

## 18. 练习

1. 手动模拟容量 4 的环形队列：push 10、20、30；pop 两次；push 40、50、60。写出每一步 head/tail/count。
2. 修改完整实现，使满时覆盖最旧元素。
3. 为事件总线增加 `peek`，但不弹出事件。
4. 设计多级菜单树，并说明返回上级需要保存什么。
5. 比较固定数组和链表存储 8 个任务的 RAM 开销。
6. 为 2048 条 Flash 记录设计二分查找是否合适？说明数据是否物理有序以及环形回卷影响。
7. 实现一个 16 节点固定内存池。
8. 为你计划新增的功能选择数据结构，并写出选择依据和最坏复杂度。

检查点：你能根据容量、操作、实时性和内存约束选择结构，而不是根据名字熟悉程度选择。
