# 04　指针、数组、字符串与内存

## 本章目标

指针是 C 和嵌入式开发的核心。本章不要求背“指针口诀”，而是要求你能画出每一个对象的地址、大小、内容和访问路径。

完成后，你应该能解释：

- `uint8_t value` 与 `uint8_t *pointer` 的区别；
- 数组名为什么经常转换成首元素指针，但数组不是指针；
- `const uint8_t *` 与 `uint8_t *const` 的区别；
- HAL 为什么接收缓冲区地址和长度；
- OLED 1024 字节显存怎样映射 128×64 像素；
- 越界、悬空、空指针和别名为何危险。

## 1. 对象、地址和指针变量

```c
uint8_t value = 42U;
uint8_t *pointer = &value;
```

假设 `value` 位于地址 `0x20000100`：

```text
地址         内容
0x20000100   0x2A        <- value

pointer 本身也是一个变量，它保存 0x20000100。
```

- `value`：读取该地址中的 8 位数据；
- `&value`：取得对象地址；
- `pointer`：读取指针变量中保存的地址；
- `*pointer`：访问该地址指向的对象。

```c
*pointer = 100U; /* value 变成 100 */
```

指针的类型告诉编译器：解引用时读多少字节、怎样解释，以及 `pointer + 1` 前进多少字节。

## 2. 为什么指针有类型

```c
uint8_t  *p8;
uint16_t *p16;
uint32_t *p32;
```

通常：

- `p8 + 1` 前进 1 字节；
- `p16 + 1` 前进 2 字节；
- `p32 + 1` 前进 4 字节。

这叫指针算术，以“元素”为单位，不以裸字节为单位。

错误地把未对齐地址转换成 `uint32_t *` 并解引用，可能在 Cortex-M 上造成错误或性能损失。协议字节流应通过逐字节组合或 `memcpy` 读取，而不是随意强制转换。

## 3. 空指针

```c
uint8_t *pointer = NULL;
```

`NULL` 表示不指向有效对象。解引用空指针是未定义行为：

```c
*pointer = 1U; /* 错误 */
```

接口常先检查：

```c
bool read_data(void *data, size_t length)
{
    if ((data == NULL) || (length == 0U)) {
        return false;
    }
    /* ... */
}
```

检查不是装饰；它将不可预测的内存破坏转换成明确失败。

## 4. 数组是连续对象

```c
uint8_t buffer[4] = {10U, 20U, 30U, 40U};
```

假设首地址为 `0x20000200`：

```text
0x20000200  10  buffer[0]
0x20000201  20  buffer[1]
0x20000202  30  buffer[2]
0x20000203  40  buffer[3]
```

数组包含四个真实元素，大小为：

```c
sizeof(buffer) == 4U
```

在大多数表达式中，`buffer` 会转换为 `&buffer[0]`，所以可以传给需要 `uint8_t *` 的函数。但数组本身不是一个指针变量：

```c
uint8_t *p = buffer;
sizeof(p);      /* STM32F103 上通常为 4：指针大小 */
sizeof(buffer); /* 4：整个数组大小 */
```

## 5. 数组传参时长度会丢失

下面两个参数声明在函数参数位置效果相同：

```c
void process(uint8_t data[]);
void process(uint8_t *data);
```

函数不知道数组有多少元素，所以必须另外传长度：

```c
void process(const uint8_t *data, size_t length);
```

这是 HAL、`memcpy`、CRC 和 W25Q64 接口都使用“地址 + 长度”的原因。

## 6. 越界访问

```c
uint8_t data[4];
data[4] = 1U; /* 错误：合法下标是 0～3 */
```

C 通常不会自动检查边界。越界可能：

- 修改相邻变量；
- 破坏返回地址；
- 导致 HardFault；
- 暂时看似正常，数分钟后异常；
- 在 O0 正常、O2 失败。

循环应使用严格小于：

```c
for (size_t i = 0U; i < length; ++i) {
    data[i] = 0U;
}
```

## 7. 字符串

C 字符串是以 `\0` 结尾的字符数组：

```c
char name[] = "SHT30";
```

内存实际包含 6 字节：

```text
'S' 'H' 'T' '3' '0' '\0'
```

`strlen(name)` 返回 5，不包含结尾零；`sizeof(name)` 返回 6。

### 7.1 字符数组与字符串字面量指针

```c
char writable[] = "OLED";
const char *read_only = "OLED";
```

`writable` 是可修改数组。字符串字面量不应通过指针修改，所以使用 `const char *`。

### 7.2 安全格式化

项目使用：

```c
char text[16];
(void)snprintf(text, sizeof(text), "%lu", (unsigned long)count);
```

`snprintf` 接收缓冲区大小，避免无限写入。仍要检查目标是否足够大，并理解截断行为。

## 8. `const` 与指针

从右向左读：

```c
const uint8_t *p1;       /* 指向 const uint8_t 的指针 */
uint8_t const *p2;       /* 与 p1 相同 */
uint8_t *const p3 = ...; /* const 指针，指向可修改 uint8_t */
const uint8_t *const p4 = ...; /* 指针和目标都不可通过它修改 */
```

### 8.1 输入缓冲区

```c
bool transmit(const uint8_t *data, size_t length);
```

`transmit` 承诺不通过 `data` 修改内容。

### 8.2 输出缓冲区

```c
bool receive(uint8_t *data, size_t length);
```

函数将写入缓冲区，因此不能加目标 `const`。

`const` 是接口契约，也帮助编译器发现误修改。

## 9. `void *`

`void *` 可以保存任意对象地址，但不能直接解引用，因为没有元素类型和大小：

```c
void *raw = &value;
uint8_t *typed = (uint8_t *)raw;
```

项目中的用途：

```c
typedef void (*scheduler_task_fn)(void *context);
```

同一个调度器可以给不同任务传不同上下文：

```c
typedef struct {
    uint32_t counter;
} blink_context_t;

static void blink_task(void *context)
{
    blink_context_t *blink = (blink_context_t *)context;
    ++blink->counter;
}
```

代价是类型检查推迟到转换处。必须确保传入和转换使用同一种真实类型。

## 10. 多级指针

```c
uint8_t value = 1U;
uint8_t *p = &value;
uint8_t **pp = &p;
```

`pp` 指向指针变量 `p`。FreeRTOS 静态 Idle Task 回调使用多级指针输出任务控制块和栈地址：

```c
void vApplicationGetIdleTaskMemory(StaticTask_t **task_buffer,
                                   StackType_t **stack_buffer,
                                   uint32_t *stack_size);
```

函数需要修改调用者保存的指针，因此参数是“指向指针的指针”。

## 11. 生命周期与悬空指针

错误例子：

```c
uint8_t *bad_pointer(void)
{
    uint8_t local = 42U;
    return &local;
}
```

离开函数后 `local` 生命周期结束，返回的地址成为悬空指针。随后解引用是未定义行为。

可选方案：

- 由调用者提供输出缓冲区；
- 返回值而不是地址；
- 使用具有合适生命周期的静态对象；
- 在非嵌入式环境动态分配并明确所有权。

嵌入式项目优先让所有权和生命周期静态、明确。

## 12. `memcpy` 与 `memset`

```c
memset(buffer, 0, sizeof(buffer));
memcpy(destination, source, length);
```

它们按字节操作，不理解对象语义。

### 12.1 `memcpy` 的重叠问题

源和目标重叠时应使用 `memmove`。`memcpy` 对重叠区域的行为未定义。

### 12.2 指针与大小必须匹配

```c
app_snapshot_t snapshot;
memset(&snapshot, 0, sizeof(snapshot));
```

这里传的是结构体地址，长度是完整结构体大小。

错误：

```c
app_snapshot_t *snapshot;
memset(snapshot, 0, sizeof(snapshot));
```

`snapshot` 未指向有效对象，且 `sizeof(snapshot)` 只是指针大小。

## 13. OLED 显存映射

SSD1306 128×64 单色屏需要：

```text
128 × 64 ÷ 8 = 1024 字节
```

项目使用：

```c
static uint8_t s_buffer[SSD1306_WIDTH * SSD1306_HEIGHT / 8U];
```

SSD1306 按页存储，每页高 8 像素。像素 `(x,y)` 的字节索引：

```c
uint16_t index = (uint16_t)x +
                 (uint16_t)(y / 8U) * SSD1306_WIDTH;
uint8_t mask = (uint8_t)(1U << (y & 7U));
```

解释：

- `y / 8` 找到第几页；
- 每页 128 字节；
- 加 `x` 找到列；
- `y & 7` 找到该字节内的位。

点亮：

```c
s_buffer[index] |= mask;
```

熄灭：

```c
s_buffer[index] &= (uint8_t)~mask;
```

## 14. 指针与硬件寄存器

内存映射外设本质上通过固定地址访问寄存器。概念化写法：

```c
volatile uint32_t *register_address = (volatile uint32_t *)0x4001080CUL;
*register_address |= (1UL << 13U);
```

实际项目通过 CMSIS 结构体和 HAL 使用寄存器：

```c
GPIOC->ODR ^= GPIO_PIN_13;
```

`volatile` 告诉编译器每次都真正访问硬件地址，但不会自动保证并发原子性。

## 15. 别名、对齐和严格规则

如果两个不同指针可能指向同一对象，它们是别名。编译器优化依赖 C 的别名规则。把字节数组强制转换成不兼容类型并解引用可能违反：

- 对齐要求；
- 有效类型规则；
- 严格别名规则。

读取协议字段的稳妥方法：逐字节移位组合，或 `memcpy` 到正确类型后再使用。
